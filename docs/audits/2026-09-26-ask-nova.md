# Ask Nova: the documentation first, then a tool on Arc

Item b of the owner's order is better selection of services. On 26 September
the owner chose how to do it: a question box on Nova's page. Nova answers
from Arc's and Circle's documentation first, at no charge. Only when that
does not answer does it pick a tool on Arc for the question, and price it
for the owner to approve.

## Why a question box

Gate V item 4 left two things undone:
- discovery by what the question needs;
- a free documentation lookup for the question itself.

Both belong to Nova's own paid proposals. Those need a reading with an open
question, and on 26 September none of the owner's 38 readings had one. So
building either there would have changed nothing on the owner's screen.

The one purchase path in use was the owner's own question to a listed tool.
There the owner has already chosen the seller, so there is nothing to select.

The market on Arc also argued for it. 67 of the registry's 68 offers are
GETs with specialised data, for example:
- gas measured from real receipts;
- what bridging over CCTP costs;
- contract deploys;
- Argus launches.

Many take no parameter. Veyra's quote already prices a GET with no body, and
only Nova's own flow skipped them.

## What the owner sees

A box on Today, "Ask Nova". A question then goes through three steps.

1. **The documentation, free.** The answer is in the question's language and
   quotes the passages it stands on, with links. When the documentation does
   not answer, the card says what it does not say, and which pages were read.
2. **A tool on Arc, only if the documentation does not answer.** The card
   says:
   - which of the question's words the tool's own listing says;
   - how the listing describes itself;
   - what was passed over first, and why;
   - for a data tool, that it takes no question.

   Nothing is paid.
3. **Approval, signature, payment and the check afterwards.** These are the
   same as for any card.

The seller is sent the owner's own words, never a rewrite. The English search
words are for Veyra's own lookups.

## Step 1: the documentation

- **Indexes.** Both sites publish an index for agents, `llms.txt`. On 26
  September Arc's listed 63 pages and Circle's 94. Each index is read once an
  hour per server instance, from the same fixed hosts and within the same
  bounds as every other public read.
- **The reading model.** It chooses up to three pages from the index. The same
  call gives two to four English words to search the market with.
- **The pages.** Each page is read whole, as markdown, up to 60,000
  characters.
  - A long page gives the model 40 passages. These are the ones that say the
    searched words, with rarer words counting more, kept in the page's own
    order.
  - A table row keeps its section and tab, for example "Gateway, Mainnet:
    GatewayWallet | 26 | 0x7777…". A table's header row is dropped.
- **The answer.** It must name the passages it stands on. One passage id that
  was never supplied throws the whole answer out. A partial answer counts as no
  answer.
- **Failures, each said as itself:**
  - the documentation could not be read;
  - no page looked relevant;
  - the model could not be reached;
  - the answer stood on nothing.

  A failure to read is never shown as "the documentation does not say".

## Step 2: a tool on Arc

- **The search words, in order:**
  1. names the question itself uses: an acronym, a camelCase name, or a capital
     inside the sentence;
  2. the model's words;
  3. last, the words every Arc seller says, such as arc and usdc.
- **Where they are searched:**
  - Circle's catalogue, one query per word for the first three words. Only
    listings that say one of them as a whole word are kept.
  - The ERC-8004 registry snapshot.
- **Ordered by fit before the shortlist is cut and probed.** Each word a
  listing says counts:
  - more when few listings say it;
  - more when it was searched earlier;
  - a quarter when every Arc seller says it.

  A listing that says only such words is not considered.
- **The walk.** Candidates are taken in order of fit. One is passed over, with
  the reason, when:
  - Veyra would not authorise it;
  - a POST has no field for a question;
  - a GET needs a value in its address, published in its schema or said in
    words ("pass ?tx=0x…");
  - it is not priced for the exact request;
  - its price can only be paid from a Circle Gateway deposit the wallet does
    not hold.
- **When nothing fits.** A web search is the general option, and the card
  labels it as that.

## Storage and the payment path

Migration `20260926120000_nova_owner_questions`:
- **Adds** the table `nova_questions`, which holds each question, its search
  words, the documentation result and the last refusal.
- **Changes** `nova_research`:
  - `signal_id` may be empty;
  - a new column, `question_id`;
  - a check that exactly one of the two is set.

  Existing rows all point at a card, so the check holds for them.

What changes and what does not:
- **Approval** re-reads the market for the exact endpoint and body, as for a
  card. It is keyed `nova:q:<question id>`, and a question that changed since
  the price refuses.
- **Settlement** is unchanged. A verified answer is kept in memory as a
  learning, as for a card; there is no card to mark.
- **Limits:**
  - 20 questions per agent per hour, since each costs two reading-model calls;
  - $0.05 per purchase, as for any card.

## Live, without paying

The run on 26 September used:
- Arc's and Circle's live documentation;
- the local reading model (`ministral-8b`), not production's;
- Circle's live catalogue on Arc;
- production's registry snapshot, loaded into memory;
- the owner's wallet address, for a read of its Gateway balance.

It ran without database access, and nothing was signed or paid.

| Question | Documentation | Tool on Arc | Passed over |
| --- | --- | --- | --- |
| What is the GatewayWallet contract address on Arc mainnet? | Answered, quoting the row "Gateway, Mainnet: GatewayWallet \| 26 \| 0x77777777…eE" | Asked for only if the owner wants a paid tool anyway: APEX `arc-impostors`, $0.004 | Fuci `risk` and CRA `arc/wallet`: Gateway deposit only |
| Сколько сейчас стоит транзакция на Arc? (What does a transaction on Arc cost right now?) | Not answered: the docs describe how fees are set, not the fee right now | APEX `arc-gas`, measured from real receipts, $0.004 from the wallet | CRA `fees/estimate`: needs a value in its address |
| Which new tokens launched on Argus in the last day, and which look risky? | No page relevant | APEX `arc-deployers`, $0.004 from the wallet | Fuci `argus/launches`, the closer match: Gateway deposit only |

The first live runs found three faults, fixed before this was committed.

1. **The GatewayWallet row was never given to the model.** It sits past
   15,000 characters of Arc's contract addresses page, and pages were cut at
   12,000.
   - Pages are now read whole.
   - Passages are chosen by rare searched words.
   - Table header rows no longer crowd out the rows under them.
2. **Mainnet and testnet rows were indistinguishable.** Tabs are markup, and
   taking the markup out took the tab away. Every row now says its section
   and tab.
3. **The small model translated nothing, and dropped "Argus" for "arc".**
   - The prompt now has two examples.
   - The question's own names come first.
   - Earlier search words weigh more.

## Not done

- **A GET that needs a parameter.** Examples are a transaction hash or an
  address. The owner chose to go without it for now; such tools are passed
  over, and named on the card.
- **Nova's proposals from a reading still search for a web search.** They
  still need an open question, and none exists.
- **Nothing has been bought through a question yet.**
- **Production's reading model is not measured on this.** The live run used
  the local model.
